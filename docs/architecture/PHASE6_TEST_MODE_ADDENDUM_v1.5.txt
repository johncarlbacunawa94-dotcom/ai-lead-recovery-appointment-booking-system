===============================================================================
1. PURPOSE
===============================================================================

Twilio is the intended PSTN and SMS transport provider for this project.

Live Twilio provisioning requires paid carrier/account resources that are
intentionally not being purchased for the current portfolio implementation.

This addendum authorizes controlled test-mode implementation of the provider
boundary while preserving the original architectural responsibilities.

It does not redefine PostgreSQL, Retell, Edge Function, or n8n ownership.

===============================================================================
2. AUTHORIZED TEST-MODE ARCHITECTURE
===============================================================================

Phase 6 test-mode work may use:

- the real Twilio SDK and API contract;
- Twilio webhook payload formats;
- X-Twilio-Signature verification;
- controlled provider-shaped events;
- MOCK transport mode for outbound SMS;
- provider-independent PostgreSQL state;
- Supabase Edge Functions as synchronous provider boundaries;
- existing transactional outbox infrastructure;
- self-hosted n8n for asynchronous orchestration.

No real carrier delivery is required for Phases 6A through 6D.

===============================================================================
6. PHASE 6C - OUTBOUND RECOVERY SMS
===============================================================================

Status:

COMPLETE / FROZEN

Implemented components include:

- pre-send recovery SMS safety gate;
- Twilio transport adapter;
- MOCK and LIVE transport modes;
- controlled transport scenarios;
- durable outbound_message_attempts state;
- protected recovery-SMS Edge Function;
- n8n missed-call recovery worker.

Immediately before a send attempt, authoritative controls re-check:

- phone/contact resolution;
- SMS eligibility;
- DND;
- revoked consent;
- duplicate/idempotent send state.

Durable send-attempt outcomes include:

- SENDING
- PERSISTED
- REJECTED_RETRYABLE
- REJECTED_FINAL
- UNKNOWN

UNKNOWN exists specifically to avoid blindly repeating a provider-boundary
operation when the external outcome cannot be safely determined.

The deployed portfolio environment currently uses MOCK transport.

No real SMS carrier delivery is claimed.

===============================================================================
7. PHASE 6D - INBOUND REPLY AND OPT-OUT
===============================================================================

Status:

COMPLETE / FROZEN

Implemented behavior includes:

- TWILIO_INCOMING_MESSAGE outbox claiming;
- authoritative inbound-message reconciliation;
- provider MessageSid replay protection;
- exact normalized phone matching;
- preservation of ambiguous identity;
- inbound conversation persistence;
- inbound message persistence;
- deterministic STOP classification;
- deterministic consent revocation;
- deterministic DND enforcement;
- all supported SMS purposes made ineligible on opt-out;
- consent provenance;
- review routing for ambiguous / unresolved identity;
- asynchronous completion / failure through n8n.

Recognized deterministic opt-out tokens include:

- STOP
- STOPALL
- UNSUBSCRIBE
- CANCEL
- END
- QUIT

AI cannot reverse deterministic opt-out or DND state.

A controlled remote normal-reply fixture passed the full path:

provider evidence
-> outbox claim
-> inbound reconciliation
-> message persistence
-> conversation persistence
-> outbox completion

The synthetic remote fixture was then removed.

Local transactional behavior testing also verified:

- normal reply;
- replay;
- STOP;
- ambiguous normal reply;
- ambiguous STOP.
